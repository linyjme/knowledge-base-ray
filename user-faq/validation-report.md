## Unresolved source ambiguities

The knowledge base does not infer unsupported behavior where the supplied documents are inconsistent or incomplete. The main unresolved source ambiguities are:

- **Exact version 8.1.8.6 P2P workflow:** the version labels cover 8.1.8.7+ and versions before 8.1.8.6, but do not unambiguously assign the interface used by exactly 8.1.8.6.
- **Specified-recipient email protection:** the release history records the capability in both version 6.8.8.2 and version 8.1.8.3, so the corpus does not claim a single introduction date.
- **Invite-upload new-folder creation:** the release history records it in both version 6.2.8.0 and version 6.3.8.0, so the corpus preserves the duplicate release evidence.
- **“Private recipient”:** the link documentation uses this term without defining the recipient field or how that party is selected.
- **Inviter/sharer bandwidth relationship:** the source does not define the allocation direction, participants, or calculation.
- **Client upgrade behavior:** the documentation describes both silent upgrade and detect-and-prompt behavior without defining their conditions or precedence.
- **Rsync retransmission scope:** the sources describe changed-data transfer and also retransmission after a differing check without fully defining when a whole file versus changed data is sent.
- **Underlying-storage exhaustion:** configured quota behavior is documented, but the end-user symptoms and recovery behavior for exhaustion of the backing physical or object storage are not.
- **Optional multi-channel ports:** `client.md` and `firewall.md` provide conflicting values; the corpus directs administrators to the firewall guide for the installed build instead of choosing a competing matrix.
